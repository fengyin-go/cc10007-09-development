# 数据分层建模工作台

离线版数仓分层建模工具，覆盖贴源层、明细层、汇总层、应用层的表结构设计、分区策略配置、质量规则编排与血缘关系管理，数据持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/connection-service.ts 连接检查/隔离/恢复/续跑
│   ├── src/components/            共享的恢复证据面板
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 数据源连接资格（检查 / 隔离 / 恢复）

数据源管理是连接资格的主对象，数据同步与任务监控只引用它的证据，不各自维护第二份结论。

- **检查分两步**：`提交连接检查` 先冻结连接类型、认证方式、超时、重试与 SYNC 链路的快照；
  写回时按快照重新判定。检查期间配置被改，旧快照不能用新配置“补算”，写回会被标为
  `未写回-配置变更` 并保留在时间线上。
- **三类结论**：五项检查全部通过为`可连接`；任一项阻塞（类型不支持该认证、超时 < 10s、
  重试 0 次、探测握手超时等）为`隔离`；无法自动定案的（Kerberos 等外部凭据、未知连接类型、
  无 SYNC 链路、链路缺失目标端）为`待人工确认`。从没检查过是`未检查`，不等于可连接。
- **隔离的边界**：隔离只阻止新同步任务 / 续跑，已有运行记录一条都不删；恢复后续跑从失败位点
  继续（续跑起点 = 失败运行的失败位点），不回到 0 重放。
- **恢复资格**：隔离态下，必须在同一配置版本、隔离位点之后连续两次独立检查都写回`可连接`，
  再经人工填写说明确认，才变为`可连接`；单次成功响应不足以恢复。`待人工确认`由维护者基于
  最近一次写回的检查裁定。
- **并发与相反结论**：写回用启动序号加令牌仲裁。较晚启动的检查先写回即生效，较早启动的检查
  后到会被标为`未写回-并发覆盖`；人工隔离/恢复优先于自动结论（`未写回-人工裁定`）。
  相反结论的双方检查号、时间、配置版本、裁定规则与胜出方都留在“相反结论裁定”里。
- **配置版本**：连接类型、地址、认证方式、连接池、超时、重试任一变化即换配置版本，旧检查证据
  与人工确认一起失效；负责人、备注变化不影响版本。
- **一处证据两处引用**：数据同步页与任务监控页的“恢复证据”面板由
  `recoveryEvidenceFor()` 同一函数生成，内容一致，并可直接跳回数据源管理核对。
- **空态都有原因**：列表为空会区分“还没有登记”和“条件没有命中”；启动/续跑被拒会说明是
  未检查、隔离、待人工确认、配置失效还是链路缺失；续跑不可用会说明是无运行记录还是无失败点。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`；连接检查/隔离/恢复走
  `frontend/src/api/connection-service.ts`，判定规则在 `frontend/src/data/connection-check.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` / `connection-service.ts` 里改，页面组件不做业务判断；
  数据源与数据同步的通用兜底动作不会直改连接状态，必须走检查、写回、裁定与续跑流程。
- 想回到初始数据：清掉浏览器里 `data-layer-studio:entries` 与
  `data-layer-studio:connection-state` 两项，或调用 `resetModule(模块)`；
  数据源管理页的“重置连接证据”会同时清掉检查证据和示例运行记录。
